# Ubuntu host CVE scanner: vulnerability data sources & matching semantics

Research snapshot: **2026-11-13 ~13:30–14:00 UTC** (Ubuntu 26.10 "stonking" devel / 26.04 "resolute" LTS current).
Live checks against primary endpoints were run; `UNVERIFIED` = could not confirm from a primary source.

## 1. Ubuntu-specific data

### 1.1 OSV.dev Ubuntu (recommended primary: best fix-encoding)
- Ecosystem strings (verified in real records): `Ubuntu:<YY.MM>` for interim (e.g. `Ubuntu:25.10`), `Ubuntu:<YY.MM>:LTS` for LTS (`Ubuntu:22.04:LTS`, `Ubuntu:24.04:LTS`), and `Ubuntu:Pro:<YY.MM>:LTS` for Pro-only pockets (`Ubuntu:Pro:14.04:LTS` … `Ubuntu:Pro:20.04:LTS`). Canonical docs also show `Ubuntu:24.04`; OSV.dev normalizes `:LTS` away (verified: query with `Ubuntu:24.04` returns same hits as `Ubuntu:24.04:LTS`, cf. google/osv.dev#2963 closed 2024-12-16). `:Pro` is a **separate namespace** ("packages that don't go to the normal archive" — OSV maintainer in #2963): query plain **and** Pro variants and merge.
- What Canonical publishes: three record families from one source — `UBUNTU-CVE-*` (CVE triage mirror w/ priority + CVSS), `USN-*` (security notices, fixed versions), `LSN-*` (Livepatch notices). Upstream repo: `github.com/canonical/ubuntu-security-notices`, dir `osv/{cve,usn,lsn}/<ID>.json`; OSV.dev importer config in `google/osv.dev/source.yaml` (`ubuntu-cve`/`ubuntu-usn`/`ubuntu-lsn`, type git, dir `osv`, accepted ecosystem `Ubuntu`). Canonical also ships the whole set as a tarball: `https://security-metadata.canonical.com/osv/osv-all.tar.xz` (**59.84 MB**, mtime 2026-11-13 06:29 → far smaller than OSV GCS, ideal for offline).
- **Backported fixes ARE encoded**: `affected[].ranges[]` ECOSYSTEM events are `{"introduced":"0"}` + `{"fixed":"<Ubuntu dpkg version>"}`, e.g. `8.1.2-1ubuntu2.22`; for Pro-only fixes the version carries `+esmN` (e.g. `7.4.3-4ubuntu2.29+esm1`). `affected[].versions[]` lists known vulnerable Ubuntu versions. No `fixed` event ⇒ every version affected = **no fix available** (verified: php5/trusty in `UBUNTU-CVE-2025-6491`).
- Version matching: OSV.dev itself performs Debian/dpkg ordering (verified: fabricated `8.3.6-0ubuntu0.24.04.4.5` still matched range; the exact `fixed` version did not; plain `7.4.3-4ubuntu2.29` < Pro `...29+esm1`). So querying installed dpkg version is safe; still implement dpkg comparison locally as fallback.
- **Source-package indexed** (critical): advisories are keyed by *source* package; querying a binary name returns `{}` (verified: `libapache2-mod-php8.3` → no hits). Map binary→source first (local dpkg DB). Helper endpoint: `POST https://api.osv.dev/v1experimental/ubuntu/binary-to-source` body `{"ecosystem":"Ubuntu:24.04:LTS","binary_names":[...]}` (≤1000/request) → `{"results":[{"source_names":["curl"]},{}]}` (verified; note empty `{}` for unknown, e.g. `libglib2.0-0`, `bash` returned empty in test).
- `ecosystem_specific` fields: `availability` (observed `"No subscription required"` and `"Available with Ubuntu Pro (Infra-only): https://ubuntu.com/pro"`) and `binaries[]` = `{"binary_name","binary_version"}` (fixed version per binary package) → lets you attribute a fix to specific executables (e.g. `php8.3-cli` vs `php8.3-common`) and to flag Pro-gated fixes. (Canonical's OSV doc page still shows `ecosystem_specific:{}` for Pro; live data has `binaries` now — trust live data.)
- Record fields: `id`, `published`, `modified`, `upstream[]` (CVE IDs), `related[]` (USN↔CVE), `references[]` (`type: REPORT|ADVISORY`, ubuntu.com/cve.org/GHSA URLs), `severity[]` (`{"type":"CVSS_V3","score":"CVSS:3.1/..."}` + `{"type":"Ubuntu","score":"medium"}` = Ubuntu priority), `affected[]`. `aliases` absent when empty.
- API: `POST /v1/query` (one pkg+version), `POST /v1/querybatch` (bulk; returns **ids + modified only**, docs: google.github.io/osv.dev/post-v1-querybatch/), `GET /v1/vulns/{id}`. **No rate limit**; 32 MiB response cap on HTTP/1.1 (use HTTP/2). Declared data-freshness SLO: sources ≤15 min stale. API license: Aggregated data under per-source licenses; Ubuntu records **CC-BY-SA 4.0** (repo LICENSE verified).
- Cadence: Canonical repo CI commits several times/day (observed 2026-11-13: 06:26, 10:52, 13:30 UTC); OVAL/tarball ~daily 06:29–06:30 UTC; OSV GCS `Ubuntu/all.zip` last-modified 2026-11-13 12:47.
- Limitations: ingest lag hours (see §5); no per-file/executable data (package granularity only); no "fixed" for EOL/legacy leftovers (no-fix records); Pro variants must be queried explicitly; base OSV dump is huge (see §4).

### 1.2 Ubuntu OVAL XML (Canonical `security-metadata`)
- Base `https://security-metadata.canonical.com/oval/`; patterns: `com.ubuntu.<release>.{cve,usn,pkg}.oval.xml.bz2`, cloud variants `oci.com.ubuntu.<release>.*`; variants in filenames use `_`: `com.ubuntu.fips-updates_jammy.cve.oval.xml.bz2`, `com.ubuntu.realtime_noble.*`, `com.ubuntu.bluefield_jammy.*`. Releases present 2026-11-13: trusty, xenial, bionic, focal, jammy, noble, plucky, questing, resolute, stonking (+ **oracular frozen**: CVE file mtime 2026-04-22, USN file 2025-07-11 → generation stops at EOL; plucky still refreshed but 25.04 is EOL — treat as UNVERIFIED whether still maintained).
- All CVE files mtime 2026-11-13 06:30 UTC → regenerated daily; ESM/EOL releases (trusty…focal) included and contain `esm-apps`/`esm-infra` criteria (verified jammy USN def comment: "jqueryui source package in esm-apps/jammy, is affected and has been fixed (note: '1.13.1+dfsg-1ubuntu0.1~esm1')").
- CVE OVAL structure (verified): `<definition class="vulnerability" id="oval:com.ubuntu.<rel>:def:...">`, title `"CVE-x on Ubuntu <ver> - <priority>"`, `<reference source="CVE" ref_id ref_url>`, `<advisory><severity>`, `<public_date>`, `<cve href priority public cvss_score cvss_vector cvss_severity usns>`; criteria = platform `extend_definition` + `linux-def:dpkginfo_test`/`dpkginfo_state` (evr compare) per source package. stonking CVE OVAL: 12,079 vulnerability defs (26.7 MB XML). **Also carries CVSS vectors offline.**
- USN OVAL: `<definition class="patch">`, title `USN-xxxx -- ...`, CVE+USN references, description contains fixed binary versions + "Available with Ubuntu Pro", criterion comment states affected/fixed version.
- Licensing nuance: `oval/LICENSE` = **CC-BY-SA 4.0** (verified), but generated XML `<generator><terms_of_use>` says **GPLv3** — conflicting statements; confirm with Canonical before redistribution (flag: surprise).
- Limitations: OVAL is per-release and stateful (packages/versions, not executables); 10–30 MB XML per release; USN OVAL = patch presence, CVE OVAL = known-vulnerable status incl. no-fix "needed" — use CVE OVAL for reporting, USN OVAL for patch verification.

### 1.3 ubuntu-cve-tracker (source of truth behind OVAL/OSV)
- `git clone https://git.launchpad.net/ubuntu-cve-tracker` (also `code.launchpad.net`; **no GitHub mirror** — `github.com/canonical/ubuntu-cve-tracker` = 404).
- Layout: `active/` (need attention), `ignored/` (+`not-for-us.txt`), `retired/`, `meta_lists/`, `subprojects/`/`embargoed` (optional symlinks), `scripts/` (`check-cves`, `sync-from-usns.py`, `sync-from-versions.py`, `ubuntu-table`, `cve_lib.py` with release/EOL tables).
- File format per CVE: `release_<source-pkg>: <status> (<version/notes>)`; statuses `DNE|needs-triage|not-affected|needed|in-progress|pending|deferred|released|ignored`; top-level `Priority` (negligible/low/medium/high/critical), `CVSS` (`nvd:`/`ubuntu:` vectors), `Patches_<pkg>`, `Tags_<pkg>`, `PublicDateAtUSN`/`CRD`.
- Cadence: MITRE/NVD import per README = Mon (NVD), Wed (MITRE allitems), Fri (NVD recent) → **CVE publication → Ubuntu triage lag up to ~2–3 days** for non-urgent CVEs (embargoed/urgent handled ad hoc; `sync-from-usns.py` flips to `released`).
- License: no LICENSE file (404) → **UNVERIFIED**; public read but Canonical copyright, treat as reference/verification source rather than redistributable bulk feed.
- Limitation: internal-format, unstable; it is what OVAL/OSV/notices are generated from.

- Official API code/docs repo: `github.com/canonical/ubuntu-com-security-api` (routes `/security/cves.json|notices.json|releases.json`). No published SLA/rate limit found → UNVERIFIED. usn.ubuntu.com/usn-db/* links in old README are legacy, don't use.
- Cadence: real-time on USN publish (verified: USN-9091-1 published 10:18Z visible in notices.json immediately; USN-9027-2 10:30Z).

### 1.5 `ubuntu-security-status` / `pro security-status`
- Old `ubuntu-security-status` (ubuntu-advantage-tools) is superseded by **`pro security-status`** in Ubuntu Pro Client. It reports package *coverage*: counts of installed packages by archive (main/restricted, universe/multiverse, third-party, unavailable), LTS/Pro support windows, counts of pending ESM/standard security updates, and per-set lists (`--esm-infra|--esm-apps|--thirdparty|--unavailable`). **It never lists CVE IDs.**
- Machine-readable (verified docs): `pro api u.pro.packages.summary.v1`, `u.pro.packages.updates.v1` (`num_updates`, `num_esm_apps_updates`, `num_esm_infra_updates`, `num_standard_security_updates`, `updates[]{download_size,origin,package,provided_by(esm-infra|esm-apps|standard-security),status,version}`), `u.pro.status.is_attached.v1`, `u.pro.status.enabled_services.v1`, `u.pro.security.status.livepatch_cves.v1` (`fixed_cves[{name,patched}]`).
- Use for context (is the host Pro-attached/enabled? which kernel CVEs patched by Livepatch?), **not** as vulnerability DB.

### 1.6 debsecan
- Ubuntu package exists (0.4.20.1 in noble) but it is the **Debian** Security Analyzer: data comes from Debian's security tracker, `--suite` expects Debian codenames, source-package based (all binaries of a source flagged), no Ubuntu USN/ESM knowledge. **Not suitable** for an Ubuntu host scanner; ignore.

## 2. Upstream / NVD
- NVD API 2.0: `GET https://services.nvd.nist.gov/rest/json/cves/2.0` (params `cveId`, `cpeName`, `keywordSearch`, `pubStartDate/pubEndDate` ISO-8601 with offset, `resultsPerPage` ≤2000, `startIndex`); response `vulnerabilities[].cve{id,published,lastModified,vulnStatus,descriptions,metrics{cvssMetricV31[],cvssMetricV40[],ssvcV203[]},weaknesses[],configurations[].nodes[].cpeMatch[],references[]}`. API 1.0 retired. Verified live unauthenticated (HTTP 200).
- Rate limits: documented historically **5 requests/30 s without key, 50/30 s with `apiKey` header**. The NVD docs pages are JS/Cloudflare-gated from here (403/empty), so current values are **UNVERIFIED as of Nov 2026**. Budget for ≤5/30 s; cache aggressively.
- **NVD enrichment policy changed 2026-04-15** (NIST news): only CVEs in CISA KEV (goal ≤1 business day), federal-government software, and EO-14028 "critical software" get full NVD enrichment (CPE/CVSS/CWE); everything else is catalogued as "Lowest Priority - not scheduled for immediate enrichment"; ~29k backlogged CVEs (NVD publish date < 2026-03-01) moved to "Not Scheduled"; NIST no longer routinely duplicates CNA CVSS. CPE is not formally abolished, but it is no longer universal → CPE-based matching is now an unreliable primary strategy. (CSA research note 2026-04-29 estimates ~80% of new CVEs unenriched by NVD.)
- CPE pitfalls even when present: CPE 2.3 is vendor/product/version with wildcards; applicability lives only in `configurations[].nodes[].cpeMatch[]` (`versionStartIncluding`, `versionEndExcluding`, etc.); CPE has no notion of Ubuntu packages/revisions/backports; CNA-supplied CPEs are inconsistent (some kernel CVEs carry 7 CPEs, some 0 — spot checks 2026-11-13); matching requires fuzzy vendor/product heuristics and is a known false-positive/negative source.
- CVE Services / CNA data: `https://cveawg.mitre.org/api/cve/<CVE-ID>` (verified 200), api-docs at `https://cveawg.mitre.org/api-docs/`; the CVE record now includes CNA + ADP containers.
- Vulnrichment: `github.com/cisagov/vulnrichment` — CISA ADP enrichment (SSVC decision points, plus CWE/CVSS where CNA omitted), **CC0-1.0**, pushed into the CVE corpus; consume via CVE Services rather than forking.
- CSAF: CISA `github.com/cisagov/CSAF` publishes CSAF 2.0 advisories for CISA IT/OT advisories (`provider-metadata.json`); relevant only for third-party/ICS products. Ubuntu does **not** publish CSAF — Canonical publishes **OpenVEX** (`github.com/canonical/ubuntu-security-notices` `vex/`, plus security-metadata VEX).
- GitHub Advisory DB: `github.com/github/advisory-database` (CC-BY 4.0), GraphQL `securityAdvisories`, mirrored into OSV; ecosystem-native (npm/PyPI/Go/Maven/…), not Ubuntu packages — only useful for vendored language deps inside binaries.
- **When NVD/CPE is genuinely needed**: (a) CVEs for unpackaged/third-party/static binaries outside dpkg (CPE/keyword heuristics, low confidence); (b) CVSS when neither OSV nor OVAL provides a vector; (c) human references/descriptions. It is **not** needed for dpkg-managed Ubuntu software — distro data knows backports, NVD does not.

## 3. Prioritization
- **EPSS** (verified): single/batch lookup `GET https://api.first.org/data/v1/epss?cve=CVE-1,CVE-2` (max 2000 chars incl. commas ≈ 100 CVEs; `date=YYYY-MM-DD`, `days`, `epss-gt`, `percentile-gt`, `epss-lt`, `percentile-lt`, `q`; `scope=time-series` for 30-day history). Response `{status,status-code,version,"access":"private, no-cache",total,offset,limit,data:[{cve,epss,percentile,date}]}`. API is **lookup-only, explicitly not for bulk**; bulk = daily CSV `https://epss.empiricalsecurity.com/epss_scores-current.csv.gz` (fields `cve,epss,percentile`; `curl -L`; URL redirects), historical daily files `github.com/empiricalsec/epss_scores` (since 2021-04-14; model v5 since 2026-06-15). Published **daily**. License: **FIRST EPSS Usage Agreement** (permissive, free public use, attribution requested; SPDX `LicenseRef-scancode-first-epss-usage`, not OSI).
- **CISA KEV** (verified 2026-11-13): `https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json`; top level `title,catalogVersion,dateReleased,count,vulnerabilities[]` (observed `catalogVersion:"2026.11.10"`, `dateReleased:"2026-11-10T19:03:29Z"`, `count:1779`); fields `cveID,vendorProject,product,vulnerabilityName,dateAdded,shortDescription,requiredAction,dueDate,knownRansomwareCampaignUse,forensicTriage` (**new, BOD 26-04**),`notes,cwes[]`. JSON schema at `.../known_exploited_vulnerabilities_schema.json`. Cadence: irregular, several updates/week (observed latest 2026-11-10 as of 2026-11-13); UNVERIFIED exact SLA. License: US Government work — public domain/CISA terms (UNVERIFIED exact wording).
- **CVSS v3.1 / v4.0**: store the vector string, don't parse casually. v3.1 = `CVSS:3.1/` + 8 base metrics (AV,AC,PR,UI,S,C,I,A) + optional temporal/environmental; score is a spec-defined formula. v4.0 = `CVSS:4.0/` with Base/Threat/Environmental/Supplemental groups and a lookup-based scoring system (no simple formula; FIRST calculator/spec + `cvss/data-representations` JSON/XML). Specs: `https://www.first.org/cvss/v3.1/specification-document`, `https://www.first.org/cvss/v4.0/specification-document`. Use a vetted library (e.g. Python `cvss`; verify it supports v4.0 — UNVERIFIED capability, test before use) and fall back to Ubuntu priority when only `{type:"Ubuntu"}` severity exists. OVAL's `cvss_vector`/`cvss_score`/`cvss_severity` attributes are a good offline CVSS source.

## 5. Freshness / lag (measured 2026-11-13)
- CVE published → Ubuntu triage in tracker: up to ~2–3 days (Mon/Wed/Fri `check-cves` schedule, README); urgent/embargoed handled ad hoc.
- USN published → Ubuntu JSON/RSS: minutes (verified USN-9091-1 10:18Z in notices.json immediately).
- USN published → Canonical OSV repo: CI commits several×/day; tarball/OVAL regenerated ~06:29–06:30 UTC daily.
- USN published → OSV.dev: sample USN-9089-1 published 2026-11-12T20:55:34Z, OSV record `modified` 2026-11-13T11:28:27Z (~14.5 h); USN-9091-1 (2026-11-13T10:18Z) was still **absent** from `api.osv.dev` at 13:40Z (>3 h). OSV.dev's own SLO is sources ≤15 min stale after the repo updates; the observable lag is Canonical's conversion cadence, not OSV's importer. Practical: expect **hours, up to ~1 day**, for brand-new USNs to reach OSV; use the Canonical tarball/USN JSON for same-day coverage.
- OSV `UBUNTU-CVE-*` records: `published` = upstream CVE publish time-ish, `modified` = last triage update (e.g. UBUNTU-CVE-2026-109618 published 2026-10-21, modified 2026-10-28).
- KEV: new entries within days of exploitation evidence; EPSS daily; OVAL/OSV same-day.

## 6. Recommendation for the scanner (minimal viable stack)
**Preferred (online) order:** 1) Ubuntu OSV (`api.osv.dev` live / Canonical tarball) — CVE IDs, fixed dpkg versions, USN/CVE references, Pro availability; 2) Ubuntu OVAL CVE+USN XML — independent cross-check, known-vuln status incl. no-fix, offline CVSS vectors; 3) USN `notices.json`/RSS + `cves.json` — human references, priorities, notice metadata; 4) EPSS daily CSV + KEV JSON — prioritisation; 5) NVD API 2.0 — only for unpackaged/third-party binaries and missing CVSS; 6) OSV GitHub Advisory — vendored language components. **Do not** use debsecan; do not make NVD/CPE the primary matcher.
**Matching semantics (must-do):** a) detect codename/variant → query `Ubuntu:<YY.MM>[:LTS]` **and** `Ubuntu:Pro:<YY.MM>:LTS`, merge hits; b) map executable path → binary pkg (dpkg file lists `/var/lib/dpkg/info/*.list`) → source pkg + version (`/var/lib/dpkg/status` `Source:` field; fall back `dpkg-query -W -f='${Package} ${Version} ${Source}\n'`); c) query OSV by **source name + full dpkg version** (verified matching works); d) filter `affected[]` by ecosystem, compare installed vs `fixed` with dpkg ordering; no `fixed` ⇒ report "no fix available" (mark Pro-gated if `availability` says Ubuntu Pro); e) use `ecosystem_specific.binaries[binary_version]` to decide which *binary* package actually contains the fix, and attribute findings to the executable(s) from that binary; f) fall back to OVAL (CVE defs = vulnerable state, USN defs = patched state) when OSV is stale/unavailable; g) enrich with EPSS (join `upstream`/alias CVE), KEV flag (`cveID`), Ubuntu priority (`severity type=Ubuntu`) and CVSS (OSV `CVSS_V3` → OVAL `cvss_vector` → NVD); h) emit CVE + `UBUNTU-CVE` alias + USN links from `references[]`/`related[]`.
**Offline:** the §4 recipe; ship `osv-all.tar.xz` + OVAL + EPSS + KEV, daily delta refresh; api.osv.dev optional.

**Surprises / critical:** (1) NVD stopped universal CPE/CVSS enrichment on 2026-04-15 — CPE cannot be the scanner's primary matcher anymore; (2) Ubuntu OSV records are *source-package indexed* and `:Pro:`-variant records are separate — a naive binary-name or plain-only query silently misses findings (verified binary queries return `{}`); (3) no-fix records (no `fixed` event) legitimately mean "all versions affected" — a scanner that treats absent fixed as "not vulnerable" inverts the result; (4) Canonical's 60 MB OSV tarball is 13× smaller than OSV's 815 MB Ubuntu zip for offline use; (5) OVAL licensing is self-contradictory (CC-BY-SA vs embedded GPLv3) — legal review needed before redistributing.
